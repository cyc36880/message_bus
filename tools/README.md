# 消息总线设计器（message-bus-designer）

一个**单文件、零依赖、零构建**的网页工具，用来手工梳理一个工程里
「哪条总线、哪些节点、谁发布什么、谁订阅什么」。

它解决的问题很具体：节点少的时候，`grep mb_node_publish` 就能看懂全貌；
节点涨到十几个、订阅互相交叉之后，**代码本身已经不再是描述关系的好载体**，
这时候你需要一张图。

> 它同时把每个节点「照现在的配置应该长什么样」的 C 代码实时拼出来，
> 方便你直接抄进工程 —— 但**它生成的代码是给人读的样例，不是构建产物**。

---

## 直接打开

```
双击 tools/message-bus-designer.html
```

没有构建步骤，没有 Node、没有 npm、没有服务器依赖。双击就能用，
也可以直接提交进仓库、发给同事。

首次打开会载入一份示例（对应 [`examples/03_lvgl_motor_sensor.c`](../examples/03_lvgl_motor_sensor.c)），
看一遍就知道怎么用了。

## 两个视图，一个按钮切换

### ☰ 表格视图

左侧是总线/节点树，中间是每个节点的编辑卡片：

| 字段 | 对应 C API |
|---|---|
| 总线名 | `mb_bus_create(bus, name, ...)` 的 `name` |
| 发布节点上线/下线事件 | `mb_bus_config_t.publish_node_events` |
| 节点名 | `mb_node_create(bus, name, ...)` 的 `name` |
| 发布 → 主题 | `mb_node_publish(node, topic, ...)` 的 `topic` |
| 发布 → 定向目标 | `mb_node_publish_to(node, dst, subtopic, ...)`，填了就等价于把 `dst/subtopic` 拼成主题 |
| 发布 → 示例负载 | 纯文档字段，不参与任何校验，写个典型值方便别人看懂 |
| 发布 → retain | `MB_PUB_FLAG_RETAIN` |
| 订阅 → 过滤器 | `mb_node_subscribe(node, filter, ...)` 的 `filter` |
| 订阅 → 来源过滤 | `mb_subscribe_opts_t.source_filter` |
| 订阅 → nolocal | `MB_SUB_FLAG_NOLOCAL` |
| 订阅 → skip-ret | `MB_SUB_FLAG_SKIP_RETAINED` |
| 任意位置的「注释」 | 该对象在代码里说不清楚的那部分；会原样存进 XML |

### ◈ 关系图视图

自动分层排版：**发布者 → 订阅者**，连线上的标签是投递时会匹配上的主题。
通配符订阅显示成 `sensor/temp/value ⇒ sensor/+/value`，一眼就能看出
「这条线是靠 `+` 匹配上的」还是精确同名。

- **单击**方框 → 跳到表格视图里对应的节点
- **拖动**方框 → 手工调整位置，坐标会写回 XML 的 `x` / `y`；
  画布会自动铺满可视区，把节点拖到边缘之外时**画布跟着一起变大**，
  所以可以放心把图摊开（「重新自动排版」会把画布收回自动尺寸）
- **在空白处按住左键拖动** → 平移整张画布（节点位置不动，只是视野移动）。
  图摊开之后要跑去看另一半时用它；光标会变成抓手，拖节点仍然是拖节点
- **拖动连线上的标签** → 改变这条线的形状，偏移量写回 XML（见下面的 `<edge>`）；
  点中线的机会很小，所以**整条线加粗了一条透明的命中带**，点到线上任何一处都一样
- **单击连线** → 选中它并弹出一个小面板，可以**改线条颜色**或一键还原
- **Ctrl + 滚轮** → 缩放，以光标为中心（放大时光标底下还是原来那个东西）。
  范围 35% – 300%，图例右边还有 `−` `100%` `+` 三个按钮，
  点中间的百分比直接回到 100%。缩放只是视野，不进 XML、也不写进浏览器存储
- 虚线灰药丸 = **发布了但没有任何订阅者**的主题（就是 `stats.no_subscriber` 的来源）
- 总线打开了「发布节点上线/下线事件」时，`$mb/nodes/<名字>/connected` 这类
  系统主题也会画进来

### 线为什么不会叠在一起

`lvgl_ui` 和 `motor` 互相发消息时，两条线的形状本来是**算出来完全一样**的 ——
起点终点互换而已 —— 于是两条线重合、两个主题标签也压在同一个点上，
怎么拖都分不开。

所以同一对节点之间的线会被自动分组，按顺序往两侧岔开「车道」：
第一条往上让 26 px，第二条往下让 26 px，第三条往上 52 px……
反向的那条天然落在另一边。**这是自动的，不用你手动拖**；拖过之后，
手工偏移是**叠加**在车道上的，所以同组里别的线动了，你调好的这条不会跟着跑。

> 顺带一提，画布上的虚线是**在流动的**：`stroke-dashoffset` 从 16 递减到 0
> （正好一个周期，循环无缝），虚线沿路径朝终点跑 —— 也就是**从发布者流向订阅者**。
> 方向搞反的话，动画会在提示「数据倒着流」，所以这个符号别改。
> 系统里设了「减少动态效果」（`prefers-reduced-motion`）时会自动停下来。

> 布局是从 XML 算出来的，不是画上去的。改完结构图会自动重排；
> 如果你手工拖过位置，那些节点就固定住，想全部回到自动排版点
> 「重新自动排版」—— 它会把节点位置和线条的手工偏移一起清掉（颜色保留，
> 颜色是你特地挑的，不属于「位置」）。

## 生成 C 代码

表格视图里，**每条总线**和**每个节点**的标题栏右侧都有一个 `{ }` 按钮，
点开就把「这一份配置对应的 C 代码」显示在下面。默认全部关闭 —— 关着的时候
不占地方，也不需要你为不看的东西付注意力；打开状态会跟着一起存进浏览器。

分工是这样的：

| 代码块 | 内容 |
|---|---|
| **总线** | `mb_bus_t *bus = NULL;` + `mb_bus_create(...)`（关掉节点事件时改用 `mb_bus_default_config()` + `mb_bus_create_ex()`）+ `mb_bus_destroy(bus);` |
| **节点** | `mb_node_t *<名> = NULL;` + `mb_node_create(...)`、它全部的发布、全部的订阅，以及订阅对应的回调空壳 |

几条约定：

- **名字会洗成合法标识符**。`lvgl ui` → `lvgl_ui`；纯中文名洗不出标识符，
  退回 `node_1`、`node_2`（按节点在总线里的次序，不会撞名）。
- **能省就省**。没有 `retain` 的发布直接传 `NULL`，不凭空造一个 `opts` 变量；
  没有 `source` / `nolocal` / `skip-retained` 的订阅走 `mb_node_subscribe()`，
  有才升格成 `mb_node_subscribe_ex()`。
- **回调名按「节点 + 过滤器」取名**，同名自动加 `_2`、`_3` —— 同一节点订阅
  多个过滤器、或多个节点订阅同一个过滤器，都不会撞。
- **注释原样搬进去**，包括节点注释、每条发布/订阅的注释。
- 负载的 `payload_len` 数的是 **UTF-8 字节数**，不是字符数（跟 `strlen` 一致）。
- 生成的是**片段**，不是能直接编译的完整工程：回调空壳里只 `printf` 了一下，
  该换成你自己的逻辑。

### 代码是带语法着色的

类型、字符串、注释、宏、函数名各有各的颜色，扫一眼就能分清「哪部分是主题、
哪部分是负载、哪部分是参数」。着色只上色、不改字：整行的 `textContent`
和生成的源码逐字相等，所以「全选复制」出去的是干净的 C，不会被颜色污染
（这条有测试盯着）。

### 改动之后会高亮

正在显示代码时，你去改那个节点（或那条总线）的配置，**新出现/被改动的那几行**
会闪一下底色 —— 背景先亮起来再淡回去，1.8 秒，左侧还会有一条竖杠跟着淡出，
文字本身完全不动。这样你改一个字段就能立刻看到「它到底改了代码里的哪一行」，
不用自己两版对着比。

闪的是**背景**、不是文字，所以即使行很长、或者你正盯着某段字符串看，
也不影响读内容；淡完自动恢复原样，不留痕迹。

两个细节是特意做的：

- **重绘不丢滚动位置**。代码块最高 460 px，超了就自己滚。如果重绘会把
  滚动条弹回顶部，你正看着下半截时改一个字段，视野被拽走、闪的那行还在
  屏幕外 —— 看着就像「根本没高亮」。所以重绘前后会把滚动位置原样还原。
- **闪的行如果在视野外，只滚这个代码块**（不会滚动整个页面，免得把你正在
  打字的输入框顶出屏幕）。

> 代码块是**关着的时候不生成、不更新**的。想让某条总线 / 某个节点跟着你的
> 改动实时更新并高亮，得先把它的代码打开。

## 校验：和固件同一套规则

这是这个工具最值钱的部分。网页里的主题校验与匹配**不是另外写一份**，
而是 [`src/mb_topic.c`](../src/mb_topic.c) 与 [`src/mb_dispatch.c`](../src/mb_dispatch.c)
中逻辑的逐行移植。设计器判「合法」的东西，烧进 MCU 不会返回 `MB_ERR_INVALID_ARG`。

右侧面板实时列出问题，按严重程度分三档，点一条能跳到出问题的地方。

### ✕ 错误 —— 固件里会直接失败

| 检查 | 固件对应 |
|---|---|
| 总线名称为空 | `mb_bus_create()` → `MB_ERR_INVALID_ARG` |
| 总线重名 | 多条同名总线彼此独立，但一定会搞混 |
| 节点名为空 / 超长（≥ 32）/ 含 `/` `+` `#` / 以 `$` 开头 | `mb_node.c: validate_node_name()` |
| 同一总线内节点重名 | `mb_node_create()` → `MB_ERR_ALREADY_EXISTS` |
| 发布主题为空 / 超长（≥ 128）/ **含通配符** | `mb_topic_validate_topic()` |
| 定向发布的目标节点名非法 | `mb_node_publish_to()` |
| 过滤器非法：`#` 不是最后一层、`#` 没独占一层、`+` 没独占一层、空、超长 | `mb_topic_validate_filter()` |
| 来源过滤器非法 | `mb_subscribe_ex()` 里对 `source_filter` 的同一套校验 |

### ! 警告 —— 能跑，但多半不是你想要的

| 检查 | 为什么 |
|---|---|
| 主题发布了但**没有任何订阅者匹配** | 白发包，`stats.no_subscriber` 会一直涨 |
| 过滤器**匹配不到本总线上任何发布** | 要么拼写错了，要么关系还没画完 |
| 同一主题被**多个节点**发布 | 订阅者会交替收到两边的内容，界面来回跳变 |
| 同一节点存在**完全重复的订阅** | 回调会被调用两次 |
| 同一节点重复发布同一主题 | 两条定义完全等价，留一条即可 |
| 发布主题以 `$` 开头 | 按 [MQTT-4.7.2-1]，`#` 和 `+` 匹配不到它，订阅者必须显式写 `$…` |
| 定向发布的目标节点不在本总线 | `mb_node_publish_to()` 不要求目标存在，但消息会落空 |

### i 提示 —— 供参考

- 过滤器以首层通配符（`#` / `+`）开头 → **收不到** `$mb/…` 节点事件
- 节点订阅了自己发布的主题且没设 NOLOCAL → 回调会在自己的线程里被再叫一次
- 来源过滤指向的节点不在本总线内（可能来自别处，也可能是笔误）
- 设了「不接收 retained」，但设计里没有匹配该过滤器的 retained 主题（当前无影响）
- 空节点（既不发布也不订阅）

## 数据格式：XML

所有数据都是 XML —— 可读、可 diff、可以和代码一起进版本库、可以 code review。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<message-bus-design version="1.1.0">
  <meta>
    <title>温室控制器 v2</title>
    <comment>整体注释：这份设计要解决什么、有哪些约定。</comment>
  </meta>

  <bus name="app" node-events="false">
    <comment>主应用总线。</comment>
    <node name="sensor" x="120" y="40">
      <comment>ADC 采样任务。</comment>
      <publish topic="sensor/temp/value" payload="23.4" retain="true">
        <comment>retained：后启动的界面能立刻拿到当前值。</comment>
      </publish>
      <subscribe filter="sensor/+/value" source="sensor" nolocal="true" skip-retained="true"/>
    </node>

    <edge from="lvgl_ui" to="motor" topic="motor/cmd" dx="0" dy="-26" color="#4c9aff"/>
  </bus>
</message-bus-design>
```

### 属性一览

| 元素 | 属性 | 默认 | 说明 |
|---|---|---|---|
| `message-bus-design` | `version` | — | schema 版本，当前 `1.1.0`（`1.0.0` 的文件照样能读） |
| `bus` | `name` | — | 总线名 |
| `bus` | `node-events` | `true` | 为 `false` 时才写出；对应 `publish_node_events` |
| `node` | `name` | — | 节点名 |
| `node` | `x` `y` | 无 | 关系图里手工拖过的位置；没有就自动排版 |
| `publish` | `topic` | — | 主题。有 `to` 时这里放**子主题** |
| `publish` | `payload` | 无 | 示例负载，纯文档 |
| `publish` | `retain` | `false` | 为 `true` 时才写出 |
| `publish` | `to` | 无 | 定向发布目标节点名（`mb_node_publish_to`） |
| `subscribe` | `filter` | — | 主题过滤器 |
| `subscribe` | `source` | 无 | 来源过滤（按节点名匹配） |
| `subscribe` | `nolocal` | `false` | `MB_SUB_FLAG_NOLOCAL` |
| `subscribe` | `skip-retained` | `false` | `MB_SUB_FLAG_SKIP_RETAINED` |
| `edge` | `from` `to` | — | 这条线的两端，写**节点名** |
| `edge` | `topic` | — | 这条线投递的主题；一个「发布 → 订阅」组合就是一条边 |
| `edge` | `dx` `dy` | 无 | 在图上拖出来的偏移量，两个一起出现才算数 |
| `edge` | `color` | 无 | 线条颜色 `#rrggbb` |
| 任意元素内 | `<comment>` | 无 | 该对象的注释，可多行 |

`<edge>` 是 `<bus>` 的直接子元素，和 `<node>` 平级，**只写你手动改过的那些**。
没动过的线不写，位置每次按节点坐标重算。只读老版本的代码遇到 `<edge>` 会
直接忽略，所以新旧文件可以混着用。

默认值一律**省略不写**，所以最简形态非常干净：

```xml
<bus name="app">
  <node name="motor">
    <publish topic="motor/speed/status" retain="true"/>
  </node>
</bus>
```

XML 是手写友好的：注释是文本节点，多行不转义；属性值里的换行会转成 `&#10;`。
反过来，手改 XML 再导入也完全没问题。

### 关于 qos

C 结构体里有 `mb_publish_opts_t.qos` 字段，但当前实现**只支持 QoS 0**
（见 [docs/architecture.md](../docs/architecture.md) 的取舍一节）。
一个恒为 0 的字段放进设计工具只会是噪音，所以这里**没有把它做成表单项**。

## 保存 / 导入 / 导出

| 按钮 | 行为 |
|---|---|
| **保存**（`Ctrl+S`） | 有已打开的文件就写回它；否则弹「另存为」。Chrome / Edge 下走 File System Access API，能**真正写到本地磁盘上的文件** |
| **另存为…** | 总是弹文件选择框 |
| **导出 XML** | 下载一份 `.xml` 副本（浏览器不支持上面的 API 时，「保存」会自动退化成这个） |
| **导入 XML** | 读本地 `.xml` 文件并替换当前内容 |
| **清除本地自动保存** | 只清浏览器里的副本，不动你正在编辑的内容 |

另外，**每次改动都会在 500 ms 后自动存进浏览器 localStorage**
（key 为 `message-bus-designer`）—— 关掉标签页、断电、误关都不会丢。
下次打开自动恢复；恢复失败会退回示例而不是白屏。

> 注意：localStorage 是**按浏览器**存的，不是文件。想真正存档、想进
> git、想发给别人，请用「保存」或「导出」。

## 自检（改主题规则后请务必跑）

网页里那套主题逻辑和固件必须保持一致，所以它被做成可单独抽取的形式，
由 [`tests/test_topic.c`](../tests/test_topic.c) 里的**同一张用例表**来验证：

```bash
cscript //nologo tools\web-selftest.js
```

输出（正常时）：

```
message-bus-designer: 71 checks, 0 failed -- topic rules agree with the C implementation
ALL PASSED
```

失败时打印到 stderr 对应的失败项并以退出码 1 退出，CI 里可以直接用。

网页**每次打开也会自动跑同一套自检**，不通过会在界面上弹红字提示。
（命令行版本用 Windows 自带的 JScript，浏览器里跑的是同一段源码。）

## 已知限制

- **生成的代码是样例，不是构建产物**。它只覆盖「建总线、建节点、发布、订阅」，
  回调体是 `printf` 空壳；错误处理、内存策略、线程上下文都得你自己补。
  拿它当抄写模板可以，当成生成器/脚手架去接进构建系统则必定不合身。
- **不做反向导入**：不能从 C 源码里解析出总线 / 节点。XML → C 可以做，
  因为设计图里信息是全的；反过来不行 —— 节点名往往是运行时才确定的，
  主题也常常是拼出来的。
- 只描述**一条总线内**的关系。总线之间本来就互相隔离（没有全局状态），
  跨总线通信在实现里并不存在，所以工具也不画。
- Node.js / Firefox 下「保存」会退化成下载，因为 `showSaveFilePicker`
  目前只有 Chromium 系提供。
